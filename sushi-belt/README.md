# Juicy Journey · 寿司传送带

参考视频：Tasty Travels_ Merge Game-720 X 1280-2026-10-02-e017dcd9e78c75700f5182ac45e12d9b.mp4，720 × 1280，约 60.16 秒。

双击 index.html 可离线试玩；人物、食材、商标和脚本均内嵌。当前版本含 8 位顾客与 1 位厨师。

## 操作

- 点击五列备选食材中的任意一列，将最前端连续的同类食材一起送给厨师。后方不同食材继续留在该列，队列向前滑动。
- 原料先飞到厨师台面，经过切制，再变成寿司送上传送带；每一份都有独立运输、加工、传送和交付过程。
- 寿司顺时针沿圆角传送带移动。顾客只接收订单气泡里对应的种类，寿司飞到嘴边后才减数量；最后一份送达后完成该单，播放爱心和金币反馈，再换下一位顾客。
- 传送带总容量为 50，容量数字包括飞行、待加工、加工中、上带中和带上的食品。容量不足时原料留在备选栏；已被顾客取走的食品不再占带上容量。
- 满 50 格且所有等待和加工中的食品都不能满足当前顾客，持续约 3 秒会出现 Conveyor Full!，可点击 TRY AGAIN 重试。
- 完成全部 52 单后显示 Good Job!，保持最后画面；手动 RETRY 才重开。
- HINT 仅突出建议选择的列。AUTO PLAY 使用同一套队列、加工、容量和交付规则；再点一次停止，手动选择食材也可接管。
- 电脑支持数字键 1—5 选择列；声音默认关闭。

## 顶部布局、顾客与随机队列

- 总进度位于顶部独立区域；顶部两位顾客的头像与侧边订单气泡分开，头像尺寸有上限，入场不会横穿显示框。
- 顾客从 4 位扩充为 8 位：新增戴眼镜的黑发男子、银发女士、光头热带衬衫男子和深色马尾女子。每次入场从暂未在场的人物里抽选，避免同一人物立即重复坐回同一座位。
- 开场订单随机分配到四个座位；离场后打乱空座位再补位。人物与座位没有固定对应关系，同一时刻的顾客形象不重复。
- 每次手动重开生成新排列。食材队列按近期订单构成混合后分配到五列，以单份、两份为主，偶尔三份；连续同类最多 3 份。点击仍按最前端连续同类组一起出料。
- 结尾改为「52 ORDERS COMPLETED」，统计完成的订单。

## 鲷鱼替换

按用户要求，用鲷鱼料理替换视频里的饭团。第 2 种原料为带头、尾和鱼鳍的完整银粉色鲷鱼；成品为白色米饭上覆盖珍珠粉色鲷鱼片的寿司，轮廓明显不同。备选栏、加工过程、传送带、顾客订单图标和名称全部同步。

共八种料理：玉子、鲷鱼、金枪鱼、三文鱼、虾、章鱼、黄瓜和鱼籽。

## 画面与范围

还原视频的木质餐厅、红灯笼、盆栽与茶杯、中央厨师、四位顾客、圆角灰色传送带、五列长食材队列，以及 52 单目标和 50 格容量。品牌使用 Juicy Journey。食材与顾客为已生成的透明 3D 风格素材；中央主厨使用用户提供的 Sera 透明立绘，通过 Canvas 进行 2.5D 绘制；未使用视频中的原始人物模型或品牌结尾广告图。

食材类型参考视频并把饭团换为鲷鱼；队列与后续订单每局随机生成，同时配平食品总量以满足全部订单。顾客补位顺序、加工时长、传送速度和失败判定是试玩参数，无法从视频直接读取原作内部规则。顾客初始订单为金枪鱼 5、玉子 2、章鱼 6、鱼籽 6，入座位置随机。

- 超容量发送不扣原料；满带无法满足顾客时触发失败，重试恢复开场。
- 自动演示完整完成 52 单、交付全部 283 份食品，该次检查容量最高 45，剩余食品 0。此次模拟约 118 秒，使用加速推进检查；不承诺每次实际操作耗时一致。

- 顶部目标框、顾客图片和订单气泡的边界不重叠检查通过；四种横竖屏预览已更新。
